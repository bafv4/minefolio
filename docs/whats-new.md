# 新機能のお知らせ（What's New）

ヘッダー常設の新機能アイコンから、前回確認以降のリリース内容（changelog）を確認できる機能。
**ユーザーの行動を邪魔しないこと**を最優先に、プル型（ユーザーが自分で開くまで内容を出さない）で設計されている。モーダル・トースト・自動スライドイン等の自動出現UIは使わない。

## UI

- ヘッダーに新機能アイコン（lucide `Sparkles`）を常設
  - ベル・封筒アイコンは「通知」「メール」と誤解されるため使わない
  - デスクトップ: テーマ切替の右（アバターの左）
  - モバイル: ハンバーガーメニューの左
- 未読リリースがあるときだけ、アイコンに小さなドット（`bg-brand`）を点灯
- クリックでポップオーバーを表示
  - ヘッダー行: タイトル「新機能」+ バージョンBadge（未読複数時は「未読 N件」）+ 日付
  - 単一バージョン表示時はカテゴリバッジ（`### 見出し` から自動抽出）を表示。**バッジをクリックすると本文内の該当セクションへスクロール**（`prefers-reduced-motion` ではスムーススクロール無効）
  - 本文: changelog該当セクションのmarkdown描画（`max-h` 内スクロール）
  - フッター: `/developers/changelog` への「すべての更新履歴を見る」リンク
- 未読がないときもアイコンは残り、いつでも最新リリースの内容を開ける（常設導線）

## 未読判定・既読化

「久しぶり」の判定は日数ではなく**バージョン差分**で行う。

| 状態 | 挙動 |
| --- | --- |
| localStorage にキーなし（初回 or 導入時の既存ユーザー） | **未読扱い**。最新1件のみを未読として表示（全履歴は積まない） |
| 既読バージョン = 最新 | 未読なし（ドット消灯） |
| 既読バージョン < 最新 | それより新しいエントリを**新しい順にすべて積んで表示**（最大5件、超過分は「ほか N 件」+ 更新履歴リンク） |
| 既読バージョンがchangelogに見つからない | 全件を未読扱い（表示は最大5件） |

- **既読化はポップオーバーを開いた瞬間**。閉じ方（ESC・外側クリック等）による意味の違いは作らない。開くと表示中の全バージョンがまとめて既読になる
- **patchリリースでも点灯する**。changelog.md に新しいバージョン見出しを書いたら点灯する、という運用に一本化（バージョン種別による分岐は持たない）

## 永続化

- localStorage キー: `minefolio_whats_new_seen`、値はバージョン文字列のみ（例 `"v1.6.0"`）
- Cookie同意のゲートは不要（テーマ設定と同じ機能上必須のストレージ扱い。個人データを含まない）
- localStorage が使えない環境では既読が永続化されず、ドットが点灯し続けるだけ（操作は阻害しない）
- ヘッダーにはデスクトップ用・モバイル用の2インスタンスがあるため、既読化時に同一タブ内イベント（`minefolio:whats-new-read`）で両者のドットを同期する

## 実装

| ファイル | 役割 |
| --- | --- |
| `app/lib/changelog.ts` | `parseChangelog(md)` / `unreadEntries(entries, seen)`。純関数（import なし） |
| `app/lib/__tests__/changelog.test.ts` | パースの成功系・失敗系 + 実際の changelog.md がパースできることのCI保険 |
| `app/components/whats-new.tsx` | アイコンボタン + Popover 本体。`@/content/changelog.md?raw` をモジュールレベルで一度だけパース |
| `app/components/whats-new-markdown.tsx` | 本文のmarkdown描画。**`React.lazy` で開いた時にだけロード**（react-markdown 一式を共通チャンクに入れないため） |
| `app/components/layout/header.tsx` | 設置箇所（デスクトップ/モバイルの2箇所） |
| `app/lib/messages/pages-ja.ts` | `whatsNew.*` 文言 |

- SSR整合: 初期stateは常に「未読なし」で、localStorage 判定は初回マウントの `useEffect` に閉じ込める（`cookie-consent.tsx` と同じパターン）。ハイドレーション不一致は発生しない
- フェイルセーフ: changelog の見出しフォーマット（`## vX.Y.Z（YYYY/MM/DD）`・全角括弧）に一致しない場合、パース結果が空になり**ドットなしの通常状態**に静かにフォールバックする（ポップオーバーを開くとタイトル行 +「更新情報を読み込めませんでした」メッセージ + 更新履歴リンクを表示）
- markdown 描画チャンクの取得に失敗した場合（再デプロイ後の旧タブ等）は、markdown 原文のプレーンテキスト表示にフォールバックし、ページ全体をエラーに落とさない

## 運用ルール

- リリース時は `app/content/changelog.md` の先頭に `## vX.Y.Z（YYYY/MM/DD）` 見出しでセクションを追加するだけでよい（それが自動的に告知になる）
- 見出しフォーマットが崩れると通知が黙って出なくなる。`pnpm test` の changelog.test.ts が先頭セクションのパース可否を検証しているので、リリース前にテストを通すこと
