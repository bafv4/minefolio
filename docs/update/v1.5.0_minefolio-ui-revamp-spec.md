# Minefolio UI/UX 改修仕様書

- 対象バージョン: v1.4.0 起点
- 技術スタック前提: React 19 / React Router 7 / TypeScript / Tailwind CSS 4 / shadcn-ui(Radix) / Drizzle(Turso)
- 本書の位置づけ: 既存実装の「作り直し」ではなく、**仕上げ・一貫性・アクセシビリティの底上げ**を行うための改修仕様

---

## 0. 設計原則（全改修共通）

1. **Radix/shadcn の既存プリミティブを最大限使う。** 手組みの `fixed` オーバーレイやスクロール制御は、`Dialog`/`Sheet`/`ScrollArea` 等に寄せる。フォーカストラップ・Escape・フォーカス復帰・`aria-*` を自前で再実装しない。
2. **キーボードとスクリーンリーダーで完結する導線を最低1本確保する。** マウス・ホバー前提の操作には必ず代替手段を用意する。
3. **動きは `prefers-reduced-motion` を尊重する。**
4. **WebGL/重いビューワは「見える時だけ」マウントする。**
5. 既存の良い実装（focus-visible リング、Skeleton、空状態、見出し階層、`lang="ja"`）は維持し、欠けている所だけ補う。

---

## 1. 横断的アクセシビリティ改修（全ページに効く）

### 1.1 スキップリンク（新規）
- `app/routes/_layout.tsx` の `<main>` に `id="main-content"` を付与。
- `<Header>` の直前に、フォーカス時のみ表示されるスキップリンクを追加。
  ```tsx
  <a href="#main-content"
     className="sr-only focus:not-sr-only focus:fixed focus:top-2 focus:left-2 focus:z-[100]
                focus:rounded-md focus:bg-primary focus:px-4 focus:py-2 focus:text-primary-foreground">
    本文へスキップ
  </a>
  ```
- 受け入れ基準: Tab 一発目でスキップリンクにフォーカスが当たり、Enter で本文先頭へ移動する。

### 1.2 モバイルメニューの Sheet 化（重要 / `header.tsx`）
- 現状: `fixed inset-0` の手組みオーバーレイ。フォーカストラップなし / `aria-modal` なし / Escape 不可 / 閉じた後トリガーへフォーカスが戻らない / ハンバーガーに `aria-expanded`・`aria-controls` なし。
- 改修: 既存の `app/components/ui/sheet.tsx`（Radix Dialog ベース）へ全面置換。
  - `SheetTrigger` をハンバーガーボタンに。`Sheet` が `aria-expanded`/フォーカストラップ/Escape/フォーカス復帰を自動で担保する。
  - `side="right"`（または `top`）でスライドイン。
  - メニュー内リンクへ `onClick` で `setOpen(false)` 相当を Radix の `onOpenChange` に委譲。
- 副次効果: `document.body.style.overflow = "hidden"` の手動スクロールロックを削除できる（Radix がスクロールロックを管理）。

### 1.3 仮想キーボードのラベル付与（`virtual-keyboard.tsx`）
- 現状: キーは `<button>` でフォーカス可能だが、中身が `text-[7px]`〜`text-[9px]` の断片テキストのみ。スクリーンリーダーが文脈を読めない。
- 改修:
  - 各キー `<button>` に `aria-label` を付与。例: `aria-label={`${keyLabel} キー: ${actionName}${remap ? `（リマップ先 ${remapLabel}）` : ""}`}`。
  - 指割り当ては**色のみ**で区別している。色覚多様性のため、キー内に指の略号テキスト（小・薬・中・人・親 等）または凡例との対応を併記する。
  - 極小フォント（`text-[7px]`〜`text-[9px]`）は、ホバー/フォーカス時にツールチップで原寸表示するか、キーサイズに応じて段階的に出し分ける。

### 1.4 検索入力の名前付け（`browse.tsx` ほか検索のある全画面）
- placeholder のみで `<label>`/`aria-label` を持たない入力に `aria-label="走者を検索"` 等を付与（placeholder はアクセシブルネームの代替にならず、入力時に消える）。

### 1.5 reduced-motion ガード（`app.css`）
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
- 対象になりうる動き: `transition-all`、ボタンの `active:scale-[0.98]`、ヒーローの blur グラデーション、`NavigationProgress`、スキン回転アニメ等。

### 1.6 テーマトグル（`theme-toggle.tsx`）
- `sr-only` ラベルが英語 "Toggle theme" → 「テーマを切り替え」に日本語化。
- 現在状態を読み上げるため、`aria-pressed` もしくは状態を含むラベル（例: ダーク時「ライトモードに切り替え」）にする。

### 1.7 FloatingSaveBar（`floating-save-bar.tsx`）
- 非表示時も DOM に残り `opacity-0 pointer-events-none`。非表示時 `aria-hidden="true"` を付与。
- 「未保存の変更があります」を `aria-live="polite"` 領域に置き、状態変化をスクリーンリーダーへ通知。

### 1.8 ランドマーク整理
- デスクトップ/モバイルで `<nav>` が複数あるため `aria-label`（例: "メインナビゲーション" / "モバイルナビゲーション"）で区別。

## 2. デザイントークン / ビジュアルアイデンティティ

### 2.1 ブランドアクセントの導入（`app.css` の `:root` / `.dark`）
- 現状: shadcn デフォルトの slate。`--primary` がほぼ黒(light)/ほぼ白(dark)で、CTA・アクティブナビ・リンクが全てモノクロ。Minecraft RTA の「らしさ」がUIに出ていない。
- 改修方針: 中立色は維持しつつ、**ブランドアクセント1色**を導入し、主要導線（primary ボタン / アクティブナビ / リンク / フォーカスリング）に適用。
  - 候補: エメラルド系グリーン（草/エメラルドブロック）または ダイヤ系シアン。
  - 既存のセマンティック変数構成に合わせ、`--brand` と `--brand-foreground` を追加し、`--primary` を置き換えるか `--accent`/リンク色に割り当てる。
- 注意: アクセント採用後も後述 2.2 のコントラスト基準（テキスト 4.5:1、UI/グラフィック 3:1）を必ず満たすこと。

### 2.2 コントラスト修正
- light モードの `--muted-foreground` が約 **4.77:1**（AA ぎりぎり）。`text-xs`/`text-[11px]` で多用され、キーボードでは `text-muted-foreground/50`・`/40` まで重ねており**基準割れする箇所がある**。
- 改修:
  - light の `--muted-foreground` を一段暗くして余裕を持たせる（目標 5.5:1 以上）。
  - 既に muted な色へさらに `/50`・`/40` の不透明度を掛ける書き方を禁止（最低でも `/70` まで）。
- dark モードは 6.7〜7.7:1 で問題なし。

### 2.3 背景パターンの多重がけ抑制（`app.css` body）
- `body` 全面のドット＋グリッドに加え、ホームのヒーローでさらにグリッド＋blur を重ねている。
- 改修: body パターンの不透明度を下げる、またはパターンをヒーロー等の限定領域に閉じ込め、本文領域は素地にする。

### 2.4 共有カード（meta）
- ホームの meta が `twitter:card: summary` + `icon.png`。コア用途が「SNS共有」なら、動的OG（`og-image.tsx`）をプロフィール等で `summary_large_image` に。リッチカードで共有時の見栄えを揃える。

## 3. 個別機能改修仕様

### 3.1 /browse、/rankings — ページネーション → スクロール遅延読み込み

#### 現状
- `loader` が `page`/`offset`/`limit`(`ITEMS_PER_PAGE`) のオフセット方式。`totalPages` を算出し、下部に番号付きページャを描画（`browse.tsx:712` 付近）。
- お気に入りは「取得済みページ内」で先頭に並べ替え（`sortedPlayers`）。
- 検索/フィルタ/ソートは `searchParams` 駆動で、変更時に `page` を delete してリセット。

#### 改修仕様
1. **初回はSSRで1ページ目を返す（SEO・no-JS 維持）。** 既存 loader のオフセット取得はそのまま流用可。
2. **追加読み込みは資源ルートで JSON を返す。** 新規 `app/routes/api/browse.ts`（resource route）を追加し、`q`/`sort`/`role`/`edition`/`input`/`platform`/`page`（or `cursor`）を受けて `players` 配列と `hasMore` を返す。loader 本体のクエリ構築ロジックを共通関数へ抽出して二重実装を防ぐ。
3. **クライアントは `useFetcher` + IntersectionObserver。**
   - リスト末尾にセンチネル `<div ref={sentinelRef} />` を置き、可視化で `fetcher.load(/api/browse?...&page=${next})`。
   - 取得結果は既存配列へ**追記（append）**。`hasMore=false` で監視停止。
4. **アクセシブルなフォールバックを必須にする。**
   - センチネルと併せて、**可視の「もっと読み込む」ボタン**を必ず置く（IntersectionObserver と同じハンドラを呼ぶ）。これによりキーボード/スクリーンリーダー/no-JS ユーザーも前進でき、無限スクロールでフッターに到達できない問題を回避。
   - 追加読み込み完了時、`aria-live="polite"` で「{n}件を追加で読み込みました」を通知。
5. **フィルタ/検索/ソート変更時はリストを破棄して再取得（page=1 から）。** `searchParams` 変更を依存にリセット。
6. **お気に入り先頭表示の扱い（要決定）。** 現状の「ページ内ソート」は append 方式と相性が悪い。
   - 推奨A: お気に入り並べ替えを**クエリの ORDER BY に組み込む**（`CASE WHEN slug IN (...) THEN 0 ELSE 1 END` 等）。全件で一貫した順序になり append でも破綻しない。
   - 代替B: 仕様簡素化として、お気に入り先頭表示は廃止し `/favorites` に分離。
7. **スクロール位置復元。** プロフィールへ遷移→戻る で読み込み済み件数と位置を保てるよう、読み込み済みページ数を `searchParams`（`page`）または `sessionStorage` に保持する方針を選択。RR7 の `ScrollRestoration` と整合させる。

#### 受け入れ基準
- JS無効でも1ページ目が表示され、`/browse?page=2` で2ページ目に到達できる。
- スクロールで自動追記され、「もっと読み込む」ボタンでも同じ追記ができる。
- フィルタ変更で先頭から再構築される。
- 追加読み込みが `aria-live` で通知される。

### 3.2 /keybindings — スクロール二重化の解消

#### 現状
- 比較テーブルが `<div className="relative border rounded-lg overflow-auto max-h-[600px]">` で囲まれ、**内側に縦スクロール（max-h + overflow-auto）** が発生。ページ自体の縦スクロールと合わせて二重スクロールになっている（該当: `keybindings.tsx:540, 583, 619, 808`）。
- ヘッダ/先頭列は内側コンテナ基準の `sticky top-0` / `sticky left-0`。

#### 改修仕様
1. **内側の縦スクロールを廃止。** 各テーブルラッパを以下に変更:
   - `max-h-[600px] overflow-auto` → **`overflow-x-auto`**（横スクロールのみ残す。比較テーブルは列が多く横は必要だが、縦はページ側に一本化）。
2. **縦の sticky はページ基準に切り替える。**
   - 列見出し行の `sticky top-0` → **`sticky top-16`**（アプリヘッダ高 `h-16` 分のオフセット）。`z-index` は既存ヘッダ(`z-50`)未満・本文以上に調整（例 `z-30`）。
   - 先頭列の `sticky left-0` は横スクロール用なので**維持**。
3. これにより縦スクロールは「ページ1本」、横スクロールは「幅広テーブルのみ1方向」になり、入れ子スクロールが解消する。
4. **`overscroll-behavior`** は縦入れ子が無くなるため不要。横スクロール領域には `overscroll-behavior-x: contain` を付け、ページ横揺れを防止。
5. **モバイル配慮。** 横スクロール可能であることを示すため、初回に右端がわずかに見切れるレイアウト、もしくは「← 横スクロールできます」のヒントを `sr-only` 併記で表示。

#### 受け入れ基準
- ページの縦スクロールが1つだけになり、テーブル上でホイール/スワイプしても入れ子の縦スクロールが起きない。
- 縦スクロール時、列見出しがアプリヘッダ直下に貼り付く（隠れない）。
- 横方向は従来どおりスクロールでき、先頭列は貼り付いたまま。

### 3.3 /player/:slug — 3Dスキンのモーダル化

#### 現状
- プロフィールヘッダに `MinecraftFullBody` を **`interactive` でインライン表示**（`profile.tsx:856` 付近）。常時 WebGL コンテキストが起動。
- `MinecraftFullBody` は既に **`asImage`（静止画・操作不可）** と **`interactive`** の両モードを実装済み（`minecraft-fullbody.tsx`）。静止画は `imageCache` でキャッシュ。

#### 改修仕様
1. **ページ上は静止3D表示に変更。**
   - `MinecraftFullBody` を `asImage` で描画（固定ポーズ・固定アングル、操作不可）。
   - これを `DialogTrigger`（`ui/dialog.tsx`）でラップした **`<button>`** にする。`aria-label="スキンを3Dで表示"`。
   - ホバー/フォーカス時に拡大アイコン（`Maximize2` 等）のオーバーレイと、わずかな `ring`/カーソル変化で「開ける」ことを示す。
2. **クリックでモーダルを開き、その中だけ `interactive`。**
   - `Dialog` 内に `MinecraftFullBody ... interactive showInteractiveHint` を配置。
   - **遅延マウント**: interactive ビューワは `Dialog` が `open` の時のみマウント（`{open && <MinecraftFullBody interactive .../>}`）。閉じたら skinview3d の WebGL コンテキストを `dispose()` して解放。ページに常時 WebGL が乗らない状態にする。
   - モーダル内にポーズ切替（standing/walking/running/waving/sitting/custom）やリセットなどの操作 UI を集約。
3. **アクセシビリティ。** `Dialog` がフォーカストラップ・Escape・フォーカス復帰を担保。`DialogTitle`（例「{表示名} のスキン」）を必ず置き、装飾のみの場合も `sr-only` で見出しを提供。
4. **パフォーマンス/モバイル。** 同時に存在する WebGL は最大1。モバイルではモーダルをほぼ全画面にし、`skinViewSize` をビューポート基準で算出。静止画は軽量（キャッシュ済み）なので一覧的なプロフィールでも負荷増にならない。

#### 受け入れ基準
- 初期表示では WebGL が起動せず、静止画のみが見える。
- 静止画をクリック/Enter でモーダルが開き、その中でドラッグ回転などの操作ができる。
- モーダルを閉じると WebGL が解放され、再度開くまで起動しない。
- キーボードのみでトリガー→操作→Escape クローズ→元のトリガーへフォーカス復帰が成立する。

### 3.4 ガイド編集ページ UI/操作性改善（`components/guide-editor/index.tsx`）

#### 現状
- Tiptap ベースの Notion 風エディタ。**3種の操作面が併存**:
  1. 常時表示のスティッキー上部ツールバー（`sticky top-0 z-40`、整形ボタン群）
  2. テキスト選択時の浮動メニュー（`position: fixed` のバブルメニュー）
  3. ブロックハンドル（ホバーしたブロック左に `position: fixed` で出るドラッグ/ブロック種別メニュー）
- オートセーブは debounce 2000ms（`useDebounced`）+ 手動保存 + 公開トグル。保存状態は小さなテキスト表示。
- ブロックハンドル/浮動メニューは**ホバー（マウス）前提**で、タッチ端末では出ない。

#### 改修仕様

**(A) 操作モデルの整理（冗長の解消）**
- 競合する3面を、役割で明確化する:
  - **インライン整形（太字/斜体/リンク/コード等）** → 選択時のバブルメニューに集約。
  - **ブロック挿入（見出し/リスト/コールアウト/コードブロック/トグル/画像/埋め込み）** → **スラッシュコマンド `/`** を新設（後述B）。
  - **ブロック操作（ドラッグ移動/種別変更/削除）** → ブロックハンドルに集約。
- 上記が揃ったら、常時スティッキーのフル機能ツールバーは**冗長**。デスクトップでは撤去 or 最小化（Undo/Redo・保存・公開のみ残す）し、**整形系はバブル＋スラッシュに寄せる**。ただしモバイルはホバーが無いので (C) の常設コンパクトツールバーで担保する。

**(B) スラッシュコマンドの新設**
- `/` 入力でブロック種別候補（既存 `blockTypeOptions` を流用: テキスト/見出し1-3/箇条書き/番号付き/引用/コードブロック/コールアウト/トグル + 画像/動画埋め込み/ガイドリンク）をフィルタ付きで表示。
- 候補メニューは**矢印キー＋Enter で完全にキーボード操作可能**にする。`role="listbox"`/`option` と `aria-activedescendant` を付与。
- Tiptap の suggestion ユーティリティ（`@tiptap/suggestion`）で実装。

**(C) モバイル/タッチ対応（最大の欠落）**
- ホバー前提のブロックハンドル・浮動メニューはタッチで出ない。
- 改修:
  - ブロックを**タップでアクティブ化**したらハンドル（種別変更・削除・移動）を表示。
  - 画面下部または上部に**常設のコンパクトツールバー**（整形＋ブロック挿入の主要操作）を設け、`@media (hover: none)` または `pointer: coarse` で出し分け。
  - 浮動メニューの座標計算（`position: fixed` + 選択 rect）はモバイルのソフトキーボード表示でずれやすいので、モバイルでは下部固定バーに置換。

**(D) 保存・編集状態のフィードバック**
- 保存ステータス（saving/saved/unsaved）は小さなテキストのみ。`aria-live="polite"` 領域にし、状態変化を通知。「保存しました（HH:MM）」のように最終保存時刻を表示。
- **未保存離脱の警告**: RR7 の `useBlocker`（およびタブ閉じ用 `beforeunload`）で、未保存変更がある状態の遷移/離脱時に確認。
- debounce 2000ms は維持可。ただし手動保存ボタンは常に即時保存できること。

**(E) エディタ本体のアクセシビリティ**
- ProseMirror 編集領域に `role="textbox"`（複数行は `aria-multiline="true"`）と `aria-label="ガイド本文"` を付与。
- 浮動メニュー/バブルメニューは、キーボードで選択した状態からも到達できる導線を確保（Tab で入れる、もしくは整形はショートカット＋スラッシュで代替可能にする）。
- **画像に alt テキスト入力欄を追加**（ガイド画像のアクセシビリティ。挿入/編集時に alt を設定可能にし、`ImageNodeView` に反映）。
- 画像リサイズがマウスドラッグのみ → タッチ対応、またはサイズ選択（S/M/L/原寸）の離散UIを併設。

#### 受け入れ基準
- マウスを使わずに、スラッシュコマンドとショートカット/バブルメニューで主要なブロック挿入・整形ができる。
- タッチ端末でブロックの種別変更・削除・整形ができる（ホバー非依存）。
- 保存状態が `aria-live` で通知され、未保存のまま離脱しようとすると確認が出る。
- 画像に alt を設定できる。

## 4. 実装フェーズ提案（労力対効果順）

**Phase 1 — 低コスト・高効果（数時間規模）**
- 1.1 スキップリンク
- 1.5 reduced-motion ガード
- 1.6 テーマトグル日本語化/状態化
- 2.2 muted-foreground コントラスト修正
